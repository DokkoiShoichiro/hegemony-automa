# 中産階級オートマ：インストラクション実装

資料：ユーザー提供 `middle class.docx`。抽出本文は同じディレクトリの `middle-class-instructions.txt`。

## 実装範囲

- PB / BC / BGS / SFM / AW のチェック。
- BC / PB / BGS / AW / SFM の実行条件と対象の選択。
- 労働者階級の従業員、サプライの熟練者、追加シフトの対象選択。
- 同産業2社・8社上限、失業者のみでの設立、最低賃金、技能・階級・誓約・全枠配置、2販売元、倉庫と購入済みエリアの区別。
- 中産階級の政策希望は 1–6 B / 7 A。政策チェックの2政策と、提議対象を選ぶための政策優先順位は別の入力。
- `MCAJudge.chooseAction` は明示された優先順位の上位2つを比較する。未知のSAを「実行不能」とみなして飛ばすことはしない。
- `applyRecords` は既存 `MiddleClass.basic/free/employ` に実行を委譲する。政策案は `policyEvent` で既存 `middlePolicy` イベントへ変換する。
- 購入比較は労働者の `cheapest`、技能の照合は共通 `fillPlan`、産業・公共サービス・同点の選択と輸出の組合せは資本家の共有関数を使用。

AIカードの番号・4チェックの並び・ボーナス・固有SA・影響力アイコンは未提供。`CARD_DATA` は空であり、実ゲームの中産階級オートマの山札やターン進行にはまだ接続していない。既存のプレイヤー手札や他階級のAIカードを流用して代用しない。

画面：3人戦の「個人ボード」で中産階級を選択し、「中産階級オートマの判断を確認」を開く。現在の盤面を変更せずに、チェックと対象選択を確認できる。UIは労働者・資本家の優先順位を中産階級のものとして扱わない。

## 2026-10-18 の照合

[公式 C&C 英語ルール v1.2](https://hegemonicproject.com/wp-content/uploads/2023/09/Crisis-Control-English-Rulebook-v1.2.pdf) 印刷p.12–13で以下を照合した。

- 購入済みの同資源がある場合、不足分を購入。既に人口分あれば人口分を新たに購入。
- 自社の販売用資源から先に購入し、足りない分を別の供給元で満たす。
- 1供給元で不足を満たし、もう1供給元に人口分の在庫があり支払える場合は追加購入する。ただし人口が増加する直前の医療を除く。
- 設立には失業中の中産階級ワーカーのみを使う。労働者階級の従業員を雇える場合は自動配置。
- 他階級の操業企業数を設立の産業比較に含めない。
- 輸出は資源ごとの販売量を最大にする（資本家と共通）。
- 割り当て効果で熟練者を得る場合、熟練者選択の自社市場に関する最初の条件を飛ばす。

[BGG掲載の公式v1.2変更履歴](https://boardgamegeek.com/filepage/275167/crisis-and-control-english-rulebook-v12) の検索結果にも、p.13の失業者限定設立・従業員自動配置の補足がある。

## 未確認：企業チェックの繁栄度加算

BGGフォーラム、関連ルール質問、公式ルール・変更履歴を検索したが、「繁栄度が完全操業企業数以下ならBC＋2」をチェック全体で1回加算するか、市場の各企業ごとに加算するか明記した回答は見つからなかった。

添付文書の段落からは全体1回とも読めるが、確定ルールとは扱わない。両解釈で移動段数が異なるとき、標準の判定は `needsReview`、`movements` は空、`alternatives` に両案を返す。呼出側が比較用に `prosperityScope: 'once' / 'perCompany'` を明示できるが、UIから仮解釈を保存・適用する機能はない。両解釈の結果が同じなら通常表示できる。

AIカード提供後に、残りのボーナス・SAと、初期優先順位・開始時/終了時処理・山札・ターン進行を接続する。
